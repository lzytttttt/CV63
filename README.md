# CV-63 / KITTY HAWK · 结构拆解与战役工作台

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

以 **USS Kitty Hawk (CV-63) / 小鹰号** 为对象的程序化 three.js 结构工作台。舰体、飞行甲板、舰岛、升降机、机库、动力舱、舰载机与武备全部由代码生成，不依赖任何外部模型；内建甲板作业动效与九个可独立拆解的功能区块。

**v1.1 新增「CIC 战役模式」**：在同一艘程序化航母上加入可玩的 10 分钟信息战推演——雷达/ESM/IFF/目视识别建立航迹，甲板调度决定出动节奏，海麻雀、密集阵、护航舰、箔条与电子干扰协同拦截“铁巢”反舰突击。玩法节奏参考《铁巢重炮 Iron Nest》以信息交互驱动的指挥体验；场景为 1989 年架空设定。

## v1.1 战役模式 / CIC COMBAT

点击右上角 **作战 / CIC · v1.1** 进入。推演在 10 分钟（600 s）内展开，可随时暂停或 1× / 2× / 4× 变速。

**一次完整的指挥循环**：`建立航迹 → 识别/判定 → 分配武器或放飞战机 → 观察交战 → 回收/补给 → 下一波`。

### 信息交互

| 手段 | 获得 | 代价 / 限制 |
| --- | --- | --- |
| SPS-48 雷达 | 带距离的空中/水面航迹，高质量 | 需 EMCON 主动；暴露自身位置 |
| E-2C 预警机 | 400 km 级早期预警，低空/导弹探测大幅提升 | 占用腰部弹射器与甲板/补给资源，需 CAP 掩护 |
| ESM 被动 | 远距离辐射源方位线，可在静默下工作 | 只有方位，没有距离；必须交叉定位才能火控 |
| IFF 询问 | 合作目标（友军/中立）5 s 内应答 | 敌机无应答不等于敌对，不能据此开火 |
| 目视识别 | CAP 抵近后确认机型与身份 | 需要时间与航线，可能暴露 CAP |
| HQ 情报 | 对单条航迹给出编队/机型提示 | 45 s 冷却，存在模糊性 |

航迹质量随传感器刷新与目标距离变化，低于 50% 或仅有方位线时不能作为火控目标。**误击民航/渔船会严重扣分**；自由开火（ROE FREE）会让 CAP 攻击未识别目标，风险由指挥官承担。

### 甲板调度

- **2 个弹射班组**：同时最多 2 架处于滑行/对位/弹射流程；**3 个补给班组**负责燃油与再武装。
- **4 部弹射器**：CAT 1/2（舰艏）与 CAT 3/4（腰部）；E-2C/EA-6B 只能使用腰部弹射器，**回收作业期间 CAT 3/4 暂停**。
- **回收**：单机进场—拦阻—脱离—滑回，占住着舰区；甲板满时着舰飞机会转入机库。
- **机库**：3 个机库位，经 E1/E2 升降机上甲板，需要空闲停机位；甲板上共 12 个停机位。
- 燃油、任务时长、返航余量、补给时间都在推演内计算；连续出动会挤占回收与补给窗口。

### 武器协同

| 系统 | 射程 / 射界 | 规则 |
| --- | --- | --- |
| Mk 29 海麻雀 ×2 | 28 km，右舷前 / 左舷后扇区 | 需要 EMCON 主动与雷达在线；每次 1 发，5.5 s 装填 |
| Mk 15 密集阵 ×2 | 1.9 km，右舷 / 左舷扇区 | 自包含雷达，静默可用；自动拦截漏网导弹 |
| CG-18 护航舰 SM-1 | 50 km，全向 | 需要呼叫，6–10 s 反应；8 发 |
| 箔条 | 11 km 内来袭导弹 | 6 发，70% 诱骗，5 s 冷却 |
| EA-6B 干扰 | 全空域 | 降低导弹末段锁定概率；可叠加干扰开关 |

多目标来袭时，需要按**射界、装填周期、航迹质量与弹药余量**分配火力；自动海麻雀可以接管来袭导弹，但会按装填顺序消耗弹药，主动规划仍然更有效。

### 核心设计

- **纯 JS 推演核心**（`src/game/`）不依赖 three.js 或 DOM，固定 0.1 s 步进，所有随机结果来自单一 seeded RNG；同一命令序列可复现。
- **CIC 控制台**（`src/game/cic.js`）负责雷达图、甲板平面图、航迹表、武器/损管与通信界面。
- **三维桥接**（`src/game/bridge3d.js`）把甲板状态映射到真实模型：牵引、升降机、挡焰板、弹射、拦阻、武器转向、拦截弹道与命中特效。
- 推演规则、平衡参数、场景与测试的完整说明见 [`docs/v1.1-combat.md`](docs/v1.1-combat.md)。

## 参数契约 / PARAMETER CONTRACT

`src/model/params.js` 是全模型唯一的尺度来源：`constants.js` 只做投影与派生，任何几何模块都不再保存"手调"的主尺度。改尺寸只改这一处，改完必须重新校验（见本节末）。

**来源**：`docs/ref/kitty_hawk_cv63_v21_revised/`（V2.1 revised 参数研究）——`cv63_parameters.json` 是可编辑参数表，`kitty_hawk_cv63_v21.js` 是同一套参数的正式实现。`params.js` 用 `CV63_SOURCE` 原样留档参考值，用 `CV63_PARAMS` 保存实际生效值；两者只差下面两处覆盖。

**1:1 采用（不缩放）**：型宽 39.5 m、吃水 10.9 m、甲板最大横截面宽 76.8 m、甲板厚度 1.2 m、着舰角 11.2°、着舰带半宽 11.5 m、贴图种子 63、12 个船体站位、17 点横剖面序列（`HULL_SECTION_SEQ`），以及四部舷侧升降机的平面位置（右舷 E1 30.5/63、E2 32.0/14、E3 29.0/−71，左舷 E4 −20.0/−103；平台 8.7–10.8 × 20.0 m，行程 10.7 m）与舰岛平面 (29.5, −26)。平台内缘按甲板轮廓凹口逐部做了 ≤0.3 m 的向外微调（ELEVATORS[].referenceX 保留参考值），避免参考参数在 3 号升降机处 0.1 个平面单位的凹陷与甲板边缘冲突。

**两处有意投影覆盖**：

| 参数 | 参考值 | 本模型 | 理由 |
| --- | --- | --- | --- |
| `dimensions.hullLength` | 318 m | 323.8 m（LOA） | 参考实现本身即以 `hullLength / 318` 作纵向缩放；采用公开总长后纵向缩放为 323.8/318 ≈ 1.0182 |
| `deck.topY` | 12.2 m | 20.6 m | 参考的 12.2 m 是与它自身 21.9 m 型深配套的概念干舷；本工作台以公开的 20.6 m 飞行甲板高度作为纵向基准 |

`deck.topY` 的覆盖不靠整体抬升舰体，而是按纵向基准映射（`VERTICAL` / `verticalMapY`）处理：水线以下 1:1 保留，龙骨 −10.9 m、水线 0 不变，因此吃水、轴系与舵桨位置不受影响。水线以上按舷侧折角线比例拉伸：参考剖面的折角线 +9.2 m 对应本模型的 +16.9 m（比例约 1.84），映射后高于折角线的型线值统一收在 +16.9 m；再由一条半宽系数 0.8（轻微内倾）的垂直舷侧带从 +16.9 m 接到甲板下缘 +19.4 m。参考模型自己的甲板下缘 +11.0 m 按同一比例会落到约 +20.2 m，高于本模型的甲板下缘，故在折角线处截断——外飘舷侧由此与机库层（+9.9 … +17.5 m）对齐，舰体壳顶与甲板下缘之间也不再留缝。

**飞行甲板平面归一化**：轮廓取自参考 `DECK_BASE` 多边形，四部升降机的凹口已经内建在轮廓里，所以轮廓本身就是含井口的甲板边缘。缩放按“同一纵向站位上的最大横截面宽 = 76.8 m”求解（参考实现记为 0.9139994）：x 方向 ≈ 0.914，z 方向 ≈ 1.0182（`z = −p · LENGTH_SCALE`，p 正值指向舰艏）。注意不能把 `maxX − minX` 当作甲板宽度——那是两个不同站位的外缘；查询交点请用 `maxDeckSectionWidth` / `planCrossSection`。甲板面积由该轮廓积分得约 15,800 m²，舰岛平面 (29.5, −26) 经同一投影落在世界坐标 (+27.0, +26.5)，即距舰艏约 0.59 舰长。甲板噪点贴图用 `seededRandom(63)` 生成，保证重复导出可复现。

**改参数后必须重新校验**：

```bash
node tools/validate_geometry.mjs
```

断言类别与参考研究的 `validate_cv63.py` 一致：甲板多边形有效性、甲板最大横截面宽、着舰中轴线角度、升降机与甲板平面的重叠率、弹射轨道是否落在甲板内。参数一改这些断言就可能失效，不能只凭渲染图判断。

## 动效序列

| 序列 | 时长 | 内容 |

| 巡航镜头 | 26 s 循环 | 环绕全舰的相机路径，烟囱烟、艏波、尾流、雷达与螺旋桨持续运转 |

连续动效：雷达旋转、密集阵/发射装置扇扫、螺旋桨与旋翼、桅杆摇摆、航行灯闪烁、海面波浪与尾流、粒子烟尘。

作战模式的实时动效（不是预录序列）：牵引车把飞机从停机位带到弹射器、挡焰板升起、蒸汽弹射、离舰爬升、拦阻着舰、升降机上下、武器站转向与开火、拦截弹道、战损火光与黑烟。状态由 `src/game/bridge3d.js` 每帧从推演状态映射，和演练序列共用同一支动画器与粒子系统。

动效实现：

- `src/anim/animator.js`：逐帧更新器 + 命名节点 + 序列时间轴 + 速度/暂停控制。
- `src/anim/sequences.js`：五个演出序列，只通过 `api`（相机、升降机、舰载机、粒子、拆解值）驱动场景。
- `src/anim/effects.js`：池化粒子（烟、蒸汽、艏波、战损爆点），提供 `funnelSmoke / steamBurst / bowSpray / impactBurst`。
- `src/model/sea.js`：GLSL 海面与尾迹（开尔文尾流、艉部翻涌、推进器尾流），与雾/色调映射管线一致。

## 说明 / 已知限制

- 模型为结构示意与可视化重排，尺寸和系统布置依据公开资料与参考图整理，不等同于原舰施工图。
- 飞行甲板平面采用的是参考研究（V2.1）的 `DECK_BASE` 轮廓，按最大横截面宽 76.8 m 归一化后投影，不是原舰施工图：局部外飘、艉部收窄与升降机凹口的过渡与实舰仍有差异，开口与支撑为结构示意。
- 干舷按公开资料取飞行甲板 +20.6 m，不采用参考研究里与 21.9 m 型深配套的 12.2 m 概念值；参考横剖面按折角线比例映射到本模型型深，因此水线以上的舷侧比例与原舰侧视照片会有轻微差别。
- 参数（尺寸、着舰角、升降机位置、轮廓控制点）改动后须运行 `node tools/validate_geometry.mjs` 复核，几何断言不通过时以校验结果为准，不要只比对渲染图。
- 参考图中的甲板标线、舰岛细节和雷达布置做了可读性强化；舰载机为低多边形识别模型。
- 海面、尾流、烟尘粒子均为实时着色器/粒子模拟，不依赖外部贴图。
- **作战模式为兵棋级抽象**：战术平面以航母为相对坐标中心，飞机/导弹以压缩时间与简化运动学表示；不模拟气动、雷达截面积分布或逐发弹药弹道。三维场景只负责甲板与武器站表现。
- 作战场景为 1989 年架空设定，舰载机、武器与编队配置做了玩法取舍；与真实历史行动无关。
- 作战模式当前为单场景、无存档；中途退出会保留推演状态，重新进入可继续。
- 首次加载会编译着色器并生成程序化贴图，低端设备建议使用桌面浏览器（建议 1366×768 以上）。
